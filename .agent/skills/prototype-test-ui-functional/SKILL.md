# UI 功能正确性测试

## 适用场景
当需要对 HTML 原型的**界面功能**进行系统性验证时使用本技能。重点检查可见功能的运行正确性。

---

## 测试检查清单

### 1. 页面渲染与初始化
- [ ] 页面可正常打开且无 JS 报错（打开浏览器控制台检查）
- [ ] 首次加载时正确渲染列表数据，并自动执行 `renderTable()`
- [ ] 空数据状态下展示占位提示，如「暂无数据」+ 图标
- [ ] 正确显示统计卡片和指标数字，可结合 `innerHTML` 赋值检查

### 2. 搜索与过滤
- [ ] **搜索字段全量参与过滤逻辑**：逐一检查 `handleSearch()` 函数，确认每个带 `<input>/<select>` 的搜索条件都在 `.filter()` 中被引用
- [ ] 搜索后同步更新表格数据和「共 X 条」计数
- [ ] 重置按钮清空所有搜索字段并恢复全量数据
- [ ] 关键词搜索采用模糊匹配，如 `includes()` 而非 `===`
- [ ] 下拉框的 `<option>` 值与数据源字段值保持一致，如 `value="待审核"` 对应 `status==='待审核'`

### 3. 分页组件
- [ ] 分页器与数据联动，搜索后同步更新总条数和页码
- [ ] 分页器不使用硬编码 HTML，避免 `<span>共 5 条</span>` 固定不变
- [ ] 翻页按钮可点击，点击后能切换数据
- [ ] 正确处理首页和末页边界

### 4. 表单与弹窗
- [ ] 新增弹窗打开时自动清空表单
- [ ] **编辑弹窗**：打开时回填当前记录数据，这是最高频遗漏项
- [ ] 必填字段校验在提交空表单时给出错误提示
- [ ] 字段长度校验通过 `maxlength` 等属性落地
- [ ] 实现手机号、身份证、邮箱等格式校验
- [ ] 点击 ✕、取消按钮或遮罩层都能关闭弹窗
- [ ] 弹窗标题明确区分「新增 XXX」和「编辑 XXX」

### 5. 状态切换与操作
- [ ] 启用/禁用切换提供二次确认弹窗
- [ ] 删除操作提供二次确认弹窗
- [ ] 状态变更后刷新列表并展示最新状态
- [ ] 按钮的禁用/启用状态逻辑正确，如已完成订单不显示「处理」按钮

### 6. 列表↔详情切换
- [ ] 点击「详情/查看」后正确切换到详情视图
- [ ] 「返回列表」按钮正确恢复列表视图
- [ ] 面包屑文字同步更新
- [ ] 详情数据与所点击的记录保持一致，而非固定数据

### 7. Tab 标签页
- [ ] Tab 切换时对应内容区正确显隐
- [ ] 当前 Tab 具备 `.active` 高亮样式
- [ ] Tab 内容正确渲染，避免空白区

## 测试方法

### 方法 A：源码静态审查
```
1. 用 view_file 逐一查看模块源码
2. 定位 handleSearch()、renderTable()、openForm()、showDetail() 等核心函数
3. 确认函数内各搜索字段都参与 filter 逻辑
4. 确认编辑入口包含数据回填代码
```

### 方法 B：浏览器动态测试
```
1. 使用 browser_subagent 打开目标 HTML 文件
2. 执行搜索操作 → 观察结果变化
3. 点击编辑按钮 → 检查表单回填结果
4. 提交空表单 → 检查校验提示
5. 截图记录测试结果
```

## 典型问题模式

1. **分页器硬编码**：`.pagination` 内容为静态 HTML，`renderTable()` 不更新分页区域
2. **搜索部分生效**：`handleSearch()` 仅实现 1~2 个字段过滤，其余字段被忽略
3. **编辑不回填**：`openForm(id)` 仅设置 `editId=id` 和修改标题，不执行回填逻辑
4. **状态值不匹配**：搜索下拉的 `value` 文本与数据数组中的字段值不一致
